Chainy Project Kanban Plan (Draft)​

This draft restructures the 29-card extraction into parallel workstreams with explicit blockers. The project cycle is September 2026 through April 2027. September–December dates fall in 2026; January–April dates fall in 2027. Overdue dates remain unchanged. Existing status and owners remain as extracted. Missing values are left unset.

Planning assumptions to confirm​

  • Approved scope follows the manuscript: offline-first, single-player Android (Android 11+), local JSON progress, no remote services, public blockchain, online leaderboard, or web/desktop release.
  • Original cards that conflict with the approved scope remain intact and are to be raised in a separate GitHub issue mentioning @Ellisia-Chan.
  • Each dependency is a finish-to-start blocker. Tasks in separate workstreams can proceed in parallel once their listed prerequisites are satisfied.
  • “Milestone” means a project checkpoint grouping deliverables; proposed dates are omitted until the date year and scope conflicts are confirmed.

Proposed reusable Codex skills for project development​

These are project-specific assistant capabilities, not team member job titles and not skills for writing the academic manuscript. Build them incrementally and keep them usable across game projects:

  1. Game Requirements & GDD — turn approved product scope into traceable requirements, mechanics, level specs, and acceptance criteria; flag conflicts rather than inventing decisions.
  2. Game Architecture & Technical Design — maintain state diagrams, subsystem boundaries, data/storage decisions, input/audio specs, and implementation-ready design notes.
  3. Game Asset & UI Pipeline — document asset conventions, import settings, low-poly/art direction, scene/UI specs, and mobile-friendly asset budgets.
  4. Unity Gameplay Implementation — support implementation tasks against the approved GDD and architecture; keep code and documentation aligned.
  5. Mobile Performance & Build — guide Android profiling, optimization records, build configuration, and reproducible packaging.
  6. Game QA & Playtest Operations — create test cases, supervised playtest protocols, issue reports, and evidence-backed QA summaries; surface participant-consent requirements for human review.
  7. Game Release & Handover — produce platform-specific release checklists, smoke-test records, user/support materials, and source handover records.
  8. Dependency-Aware Project Planner — convert approved work into workstreams, dependency edges, milestones, labels, and safe independent work packets for multitask execution.
