Part I. Scenario Understanding Points: 10 Complete the table below. Item Group Answer Selected Scenario Chainy: A 3D World Educational Game for Learning

Emerging Technology (Blockchain & AI)

Main Purpose of the Game To introduce fundamental concepts of blockchain and artificial intelligence to young beginners through an interactive 3D top-down exploration game and puzzle activities.

Target Users Elementary learners aged 6 to 12 years old (Grades 1 to 6) in Cryptita Plays outreach programs and community mini-libraries.

Main User Inputs Multi-touch gestures: on-screen virtual joystick movement, tapping to interact with 3D nodes/NPCs, drag-and-drop actions for classification puzzles, and UI button presses for quizzes.

Expected Outputs Real-time top-down 3D visuals, animated characters, visual validation and tamper-alert cues, AI data sorting feedback, background audio/SFX, star ratings, and unlockable badges.

Data or Files to be Stored Local JSON save files storing level completion flags, earned badges, quiz answers, player profile records, and custom audio/graphics settings.

Answer briefly:

  1. Which part of the game will most likely consume the most memory? The 3D environment assets, including 3D meshes, materials, and texture maps loaded during world exploration.
  2. What may happen if the device has limited RAM? The Android operating system's Low Memory Killer (LMK) may force-close the app due to Out-Of-Memory exceptions, or the game will stutter heavily during Garbage Collection sweeps.
  3. How can the group reduce memory usage? Adopt low-poly 3D models, compress all textures to ASTC/ETC2 mobile formats, use Object Pooling for recurring puzzle blocks, and unload unused scene assets between level transitions. Part III. Answer briefly:

  1. What should be tested before releasing the game? Test for a stable 30 FPS frame rate on physical budget Android test units, verify touch control responsiveness, check battery temperature, and ensure local save data persists across app restarts
  2. What device limitation may affect the game most? Limited RAM (2 GB to 3 GB) and lower-tier mobile GPUs commonly found in entry-level Android devices deployed in community libraries.
  3. What is the most practical performance improvement for the scenario? Pre-baking all scene lighting into lightmaps and using stylized low-poly assets to eliminate dynamic lighting calculations and minimize draw calls. Part IV. Answer briefly:

  2. What feature would require internet access? Only non-essential secondary features, such as remote student analytics synchronization for educators or downloading future expanded lesson packs.
  3. What should happen if the connection is slow or unavailable? The application should silently bypass network operations without interrupting gameplay or displaying blocking error popups, keeping all progress safely saved on local storage.

Part V. Final Technical Recommendation Points: 20 Write a short recommendation for the scenario. Chainy is technically feasible for elementary learners (ages 6 to 12) provided the development team adheres strictly to an offline-first and mobile-optimized architecture. Because target users at Cryptita Plays community mini-libraries and outreach centers primarily use entry-level Android devices with 2 GB to 3 GB of RAM, the system must avoid server dependencies and heavy real-time networking. The most significant technical risk involves memory usage and rendering overhead from 3D assets on low-end mobile hardware. To ensure smooth execution, the team must simplify visual complexity by using stylized low-poly 3D models, pre-baking all static lighting into lightmaps, and compressing textures using ASTC formats. Real-time dynamic shadows and memory allocations inside update loops must be eliminated in favor of object pooling. The game must remain strictly offline for its core release, bundling all three educational levels (Blockchain Verification, Tamper Detection, and AI Classification) directly inside the installation package. Development should prioritize building a functional, optimized MVP with responsive touch controls before considering any secondary online features. Minimum answer: 120 words Your recommendation must answer:

  1. Is the game technically feasible for the target users? Yes, Chainy is technically feasible for learners aged 6 to 12 at Cryptita Plays mini-library sites, provided that the application is built using lightweight mobile rendering practices and tested directly on budget Android devices.
  2. What should be simplified or optimized? The team must optimize 3D model polygon counts, compress texture atlases using mobile ASTC formats, pre-bake all static lighting instead of using real-time dynamic shadows, and implement object pooling for interactive puzzle blocks. The gameplay mechanics should also simplify complex technical jargon into intuitive, visual cause-and-effect puzzles.
  3. Should the game be offline, online, or hybrid? The game should be strictly offline for its core release. All 3D levels, interactive mini-games, and quiz question databases must be bundled directly inside the local APK build so learning is never blocked by unstable community internet connections.
  4. What is the most important technical risk? The biggest technical risk is excessive memory usage and GPU rendering strain on budget Android hardware (devices with 2 GB to 4 GB of RAM). Unoptimized 3D meshes, high draw calls, or memory leaks could trigger severe frame rate drops or force-close the app via Out-Of-Memory exceptions.
  5. What should the development team prioritize first? The development team must prioritize building and profiling a functional, mobile-optimized Minimum Viable Product (MVP) containing the core interactive levels (transaction validation, tamper detection, and AI classification) with responsive touch controls before expanding scope or adding secondary features.
