Chainy pre-final recovery plan​

Capstone project title: Chainy: A 3D World Educational Game for learning emerging Technology (Blockchain & AI)

Approved scope revision, October 8: offline foundational Web3, Blockchain and AI learning for ages 12–17, especially low-income and remote communities. The user approves a tappable lesson map, bounded ordering/linking instead of free construction, guided local replicas, a classifier prototype and a short grid agent. Full A–Z coverage is withdrawn. See governing mission and beginner materials. Existing published issue titles/estimates below remain a publication record pending synchronization, not the new feature contract. November 21 and reserved integration, beta readiness, QA, manuscript and rehearsal gates remain in force.

Original planning date: October 5, 2026; revised local forecast: October 8, 2026 (see final section). Confirmed pre-final defense: November 21, 2026, requiring 60 percent; the supplied 32-point rubric lacks actual criterion names and does not define completion. The original plan had 47 calendar days to defense; the October 8 revision has 44. User reports zero implementation progress. This is a conditional recovery forecast, not an approved claim that the schedule is feasible.

The previous 29-card plan is preserved with original IDs, owners, statuses and dates. The broader September 2026–April 2027 cycle remains. Old milestone dates do not prove delivery, and this proposed recovery plan does not change school deadlines.

Delivery recommendation​

Build a shared lesson shell and direct world-map navigation with packaged content. Use bounded record ordering/linking, guided comparison of three local copies, a prototype-validated example-trained classifier and a short fixed-grid agent. Free spatial construction and walkable exploration are deferred. Prefer reusable assets until the full lesson/save/relaunch loop works. Avoid a custom backend, teacher web dashboard, microphone features, expansive worlds and extra reward systems before pre-final.

Do not infer the school's 60 percent completion from world or lesson counts. The rubric must determine that calculation. Start with one complete lesson on a target phone, then time production of a second lesson using the same template. Use those results to reforecast the proposed nine-lesson package and integration work. A smaller scope does not establish that the existing 520-hour capacity estimate is available.

Board operating rules​

Use the private delivery board, linked to both repositories. Repository documents define requirements and decisions; issues track execution. The Trello team board synchronizes the 26 linked tasks so members can move cards, edit title/description and add comments without GitHub accounts. See sync behavior and limits. Board states: Todo, In Progress, Done; represent blockers in issue dependencies and text. A card is Done only when its acceptance evidence is linked, not when code is merely written.

Limit each person to one active implementation card where practical. Shared prerequisites and scarce skills constrain parallel work. Do not infer interchangeable available capacity from five team members or AI model access. Original source cards remain historical; CH IDs are the new recovery plan and must not silently replace their meaning.

External publication status and exact issue URLs are maintained in backlog.json. No participant records, identity maps or credentials belong in issues.
