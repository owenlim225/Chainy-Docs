Chainy current project baseline​

Capstone project title: Chainy: A 3D World Educational Game for learning emerging Technology (Blockchain & AI)

Project naming decision — October 8, 2026​

The user confirmed the exact capstone title above, including capitalization. Use it on formal project covers, the manuscript and website metadata. Use Chainy as the short product name and CHAINY in the logo. The title retains “3D World”; gameplay scope continues to follow the approved tappable three-world map and rounded 3D visual direction.

Governing mission and scope​

Deliver an offline-ready educational game for foundational learning about Web3, AI and blockchain for learners aged 12–17, especially learners in low-income and remote communities with limited access to technology. Confirmed by the user on October 8, 2026. This mission is the source of truth for product, content, design and delivery decisions.

Teach only the essential foundations needed for this capstone. The earlier request for the whole Web3 encyclopedia A–Z is explicitly withdrawn. Use the encyclopedia as a source for selected concepts and prepare beginner AI materials; source wording must be checked for accuracy. Do not assume prior knowledge of computers, cryptocurrency or AI, ownership of a phone, or access to the internet at home. Support a short touch-control introduction, plain English, readable visual examples, self-paced retries and distinct profiles on shared devices. Language and reading accessibility must be checked with the actual cohort; English first remains the current decision.

The user approves a tappable map with three worlds: Web3, Blockchain and AI, leading directly to short guided lessons. Preserve the approved toy-like 3D visual identity; walkable 3D exploration is no longer required. Defer free spatial construction and use bounded record ordering/linking. Keep guided comparison of three local replicas and a short fixed-grid observe-decide-act challenge. Validate the genuine small example-trained classifier before committing to its implementation. No cloud service is required for these lessons.

The beginner learning materials define a proposed nine-lesson content package, with examples, activities, questions and answer explanations. Nine lessons is a drafting default, not a user-mandated count or tested session duration. Scope additions must serve the mission, have an observable learning outcome and fit the protected integration, QA, manuscript and rehearsal schedule before November 21, 2026.

Device and identity planning baseline​

English first is confirmed. Team work is assigned by names; lack of GitHub accounts does not block delegation. See team packets.

The user explicitly retains Android 10+/11+, 4 GB physical RAM, 64 GB total device storage, a 64-bit ARM CPU, OpenGL ES 3.2 or Vulkan 1.1, and an entry-level-to-midrange GPU as the target specification. The working test interpretation remains Android 11+ provisionally with Android 10 as a compatibility candidate; it does not replace the supplied specification or establish tested support. The graphics path and measured minimum remain unverified. Total capacity is not the game's required space. See hardware validation.

The user proposes teacher-issued learner codes entered on each device. Adopt this as offline profile identification and pseudonymous research linkage, not verified authentication. Code entry on another device does not restore local progress. See technical design.

Single-player, Unity/C# and touchscreen controls remain the technical direction. Engine patch, render pipeline and SQLite adapter must be pinned during the device spike. No real public blockchain or online multiplayer is requested.

Recommended bounded implementation​

October 8 leaves 44 calendar days before defense, with an earlier October 30 candidate needed for the possible November 3–6 beta. Capacity is unknown, so there is no evidence-backed completion promise. The approved simpler navigation and selected foundations reduce scope, but the revised lessons still need an end-to-end device prototype and content-production timing before a delivery forecast can be validated.

Use reusable selection, sorting, sequencing and scenario templates with fixed activity views. The approved replacement for free spatial construction is bounded record ordering/linking with explanatory feedback. Three logical blockchain nodes run on one device; guided comparison replaces spatial network construction. Broader sandbox work is deferred beyond the pre-final and is not promised for a later release.

Recommend a tiny local nearest-centroid classifier over explicit numeric features of fictional objects, built in C#. Learners label examples, compute class prototypes, test held-out examples, inspect errors, and change the examples. Include deterministic ties and insufficient-example feedback. This is an actual small example-trained model, not a cloud LLM or computer vision model. Confirm the prototype meets the learning outcome before production. Algorithm reference; this reference does not prescribe a Python dependency.

Recommend one short observe-decide-act agent route with visible rules and feedback. It teaches agent behavior; do not claim it is generative AI or reinforcement learning.

Recommend no microphone, cloud sync, educator web dashboard, real cryptocurrency, content downloader, currency economy, or certificates before defense. These exclusions are recommendations where not previously confirmed, not silent removal of required features.

Supplied scoring rubric​

Four categories each contain two criteria, each scored 1–4; total 32 points. All eight share the same supplied quality descriptions: 4 exemplary (90–100 percent, production-ready or near-academic-paper standard), 3 proficient (80–89 percent, major requirements met with minor revisions), 2 developing (70–79 percent, critical functionality or significant documentation missing), 1 needs improvement (below 70 percent, incomplete or fundamental flaws). These percentages describe rating bands. They do not establish a formula for project completion or prove that a 60-percent-complete project passes. Actual criterion names and weights beyond the supplied equal points are not supplied. The later manuscript outline and mandatory deliverables are recorded below.
