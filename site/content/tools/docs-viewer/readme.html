Chainy documentation website​

The public website is hosted at https://owenlim225.github.io/Chainy-Docs/. The private Chainy repository remains the source of truth. The public Chainy-Docs repository contains generated output and its Pages workflow.

Local development​

Use Node 24 and run npm ci, then npm run dev from this directory. npm run build prepares the documents, builds the site and checks every generated document and internal link. npm test checks route handling and publication boundaries. npm run preview serves the production output locally. If the shared npm cache is unavailable, use npm ci --cache .npm-cache.

Adding and updating documents​

Edit the canonical Markdown files in this repository. All tracked or non-ignored project Markdown files are discovered automatically, including .agents skill guides and archived material. Viewer page templates, dependencies and generated files are excluded. Local previews include uncommitted documents; the automatic publisher only sees the committed checkout. Do not infer a verified change date for an uncommitted file.

The preparation script categorizes documents by source path, extracts the title and first paragraph, and builds stable routes. New files outside known categories appear under Other documents. Duplicate normalized routes fail the build. Relative links and heading fragments are validated; folder links produce directory pages. Archive documents retain their original wording and receive a historical notice.

The reader supports tables, task lists, highlighted code, images, Mermaid diagrams, heading links, local full-text search, document filters, sorting, dark mode and printing. Mermaid loads only when a document contains a diagram. The document source is escaped before rendering inside a Vue v-pre boundary so embedded HTML and interpolation remain content.

The visual theme follows the approved Chainy reference: sky blue, violet, building green and warm gold, with pale reading surfaces and a navy dark mode. Diagrams fit the available width and screen height; horizontal flowcharts reflow vertically below 768 pixels without changing their edges. SVG labels avoid inherited paragraph styles that can clip HTML labels. Full-screen views offer fit, zoom, scroll, rotation resizing and Escape-to-close; document images have the same full-size viewing option. Run node scripts/visual-check.mjs against a fresh production preview on port 4174 (or set DOCS_TEST_URL) to check the five chart-bearing documents at 320, 390, 768 and 1440 pixels.

Linked SQL, publication JSON and project media are explicitly permitted in the preparation script. New asset types require a deliberate allowance. Do not add participant records, identity maps, credentials or signing keys to source documents or attachments. The entire published document text and search index are public even though the source repository is private.

Automatic publication​

The private repository workflow .github/workflows/docs.yml validates pull requests. On matching pushes to main or a manual run, it builds and publishes generated output to owenlim225/Chainy-Docs. The public repository's workflow then deploys that output through GitHub Pages. The base path is /Chainy-Docs/.

The publisher uses a dedicated write-enabled SSH deploy key installed only on Chainy-Docs. Its private half is stored as the Chainy Actions secret DOCS_DEPLOY_KEY; it is not a general GitHub account token. Pull-request jobs do not receive that credential. The initial plan proposed a GitHub App; the implementation uses a repository-scoped deploy key to avoid requiring an additional application installation.

Pages must use GitHub Actions as its publishing source. The public repo holds only site/, a generated README and .github/workflows/pages.yml. Builds are serialized. Validation failures prevent publication and leave the last successful site available. Read publication.json on the live website to identify its source revision and included document paths.

Troubleshooting and rollback​

Inspect the private Build and publish documentation workflow first, then the public Publish documentation workflow. A passing private build alone does not prove Pages deployed. Missing document paths, duplicate routes, broken heading links or credential-like content stop the build with a source filename. Fix the canonical source and rerun.

For rollback, revert the unwanted generated publication commit in Chainy-Docs and push main; Pages redeploys the previous output. To keep that rollback in place, pause the private publisher until the source correction is ready. Never use a force push to restore the site. The same publication pipeline can be exercised without changing content through workflow_dispatch.

Scope and evidence​

This is management tooling and does not establish game implementation progress. GitHub issues remain the execution record; backlog.json remains the publication inventory. Preserve the November 21, 2026 pre-final defense and the reserved integration, QA, pilot and rehearsal time.

Dependency versions are locked. Review dependency audit output when updating; the site is statically hosted and exposes no development server. Browser and workflow acceptance evidence is recorded in the viewer delivery issue, with any unverified checks stated explicitly.
